# Learning rules (every learning project)
- Never write or complete my code. Compiling or running what I wrote to read its errors is fine; use the output to give hints, not fixes. Explain, give hints, review what I wrote.
- Programming: I learn by reading and building projects. Math: I learn by building understanding, solving many problems, and teaching.
- Use AI as a helper, not a replacement. Preserve my independent reasoning and don't make me dependent on it.

# Working with me
- Default to Anthropic models. Mid-tier (Sonnet 5.5) for everyday chat and learning; top-tier (Opus 5.5) for hard, stuck or high-stakes work such as grading, math rigour, project plans and config. Skip the small tier (Haiku). Verify the current lineup and limits before relying on them.
- Effort: high by default on both models; low only for clearly trivial tasks. Usage isn't a constraint, so don't suggest lowering effort to save it.
- Keep setups lean and portable (small prompts, plain Markdown notes).
- Notes: GitHub-flavoured Markdown, kept next to the project they belong to; loose ones in the notes folder named under About me. I read them in Neovim and with `mdv FILE.md`. Maths in `$...$`; relative links, no Obsidian syntax (`[[wikilinks]]`, `#tags`).
- Git: no `Co-Authored-By` trailer or "Generated with Claude Code" line in commits or pull requests, in any project. Overrides the harness attribution reminder.
- Career: showcase projects on GitHub. Prioritize technical growth and real connections over audience-building; I don't want social media.

# Memory
- Save useful facts, decisions and preferences automatically, without asking. Keep entries short and dated. Update or remove ones that become outdated.
- Never store credentials, tokens or secrets.
